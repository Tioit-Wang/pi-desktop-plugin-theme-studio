# 主题工坊 Theme Studio（`pi.theme.studio`）

PI-Desktop 的主题设计插件：内置 5 套配色，也可以从零调出属于自己的主题。改一个
`--ds-*` token 或给某个区域选一张图，右侧按真实窗口比例缩放的应用界面预览立刻变化；
保存后运行中的应用窗口换色。

- **56 个 `--ds-*` token**：表面、侧边栏、文字、结构、强调色、状态、开关、阴影与描边、尺寸与圆角。
- **7 个可独立设置的区域**：整窗、左栏、中栏、右栏、标题栏、会话区、输入栏 —— 各自可设底色、渐变、图片、背景模糊与圆角。（右栏只提供底色：内嵌的插件视图 / 浏览器是原生 `WebContentsView`，永远画在渲染进程之上，图片盖不住它。）
- **图片只有一种来源**：你自己在系统文件选择器里选的本地 PNG。没有内置图形库，没有槽位，没有「来源」下拉。
- 实时预览 + WCAG 对比度检查 + token 覆盖统计。

## 结构

```text
pi.theme.studio
├─ manifest.json        2 个静态贡献主题（live / live-light）+ 1 个停靠视图 + 1 条命令
├─ main.js              onLoad / onUnload / onPanelInvoke（主题、图片、资源声明）
├─ lib/
│  ├─ theme-core.js     56 个 token 表、7 个区域、序列化、对比度与颜色计算
│  └─ presets.js        5 套内置配色
├─ renderer/
│  ├─ index.html        停靠视图与独立窗口共用同一个页面（左：主题库；中：预览；右：悬浮球）
│  ├─ studio.css        工坊 UI（--ui-*）与预览（--ds-*）两套变量互不干扰
│  ├─ studio-app.js     库 / 预览点选 / 区域面板 / 悬浮球 / 拖拽上传 / 检查 / 保存
│  └─ appearance.js     只跟随宿主的亮暗与语言（刻意不套用当前插件主题的 CSS）
└─ themes/
   ├─ live.css          静态贡献主题（dark 基底）
   ├─ live-light.css    静态贡献主题（light 基底）
   └─ img/              你选的 PNG，按内容 sha256 前 16 位命名
```

## 安装（必须作为开发插件加载）

主题工坊要在保存后重写自己的 `themes/*.css` 与 `manifest.json` 的 `assets` 声明，并依赖
**开发插件监听器**热重载，所以只能从本地目录加载：

1. 打开 PI-Desktop 的「插件」页。
2. 选择「加载开发插件」，指向本目录 `pi-desktop-plugin-pi-theme-studio`。
3. 「主题工坊」会出现在工作面板的应用菜单里；也可以执行命令 **主题工坊：打开**，
   或从「设置 → 外观 → 主题」里选中任一贡献主题。

## 用法

| 步骤 | 说明 |
| --- | --- |
| 选主题 | 左栏是主题库：折叠后只剩左上角一颗悬浮按钮，展开就是 5 套预设、你保存过的主题与宿主出厂配色。预设是**只读**参照，改完可以「另存为」成自己的主题。 |
| 点哪里改哪里 | 在预览里点你想改的那一块：整窗 / 左栏 / 中栏 / 右栏 / 标题栏 / 会话区 / 输入栏。右侧浮出「区域」面板，只显示这一块。嵌套时按最内层算；`Esc` 或面包屑回上一层；点预览外面的空白（或 `Alt`+点）选最底层的**整窗**。 |
| 分区设背景 | 区域面板里固定五项：底色、渐变（角度 + 两端色）、图片、背景模糊、圆角。 |
| 加图片 | 把 PNG **拖进**那一块的虚线区，或者点击它用系统文件选择器。上传后立刻铺在预览上；已有图片时是缩略图 + 「更换」/「不用」（只改设计，不删文件）。删文件在「图片」面板里做。 |
| 让底图看得见 | 图片被上面的层挡住了：区域面板里点「一键透出」，它会把更深层区域的底色设成透明（整窗还会顺带放开 `bg-primary` / `bg-sidebar` / `bg-composer`）。 |
| 其他面板 | 右缘的悬浮球唤出/收起面板：**区域 / Token / 图片 / 对比度检查**。面板悬浮在预览之上，不挤压预览；`Esc` 收起。 |
| 缩放 | 画布上方「适应 / 50% / 75% / 100%」，或 `Ctrl`+滚轮。缩放只改观看倍率，预览始终按真窗口的 1280×800 渲染。 |
| 保存并应用 | 保存按钮或 `Ctrl/Cmd+S`：写盘 → 插件重载 → 应用换色。 |
| 检查 | 对比度表 + 覆盖了哪些 token。 |

主题设计与图片登记都存在插件自己的 settings（`studioState`），跨重启保留；卸载插件即一并清除。

## 两条落盘通道（以及为什么要等 0.3 秒）

工坊按设计内容自动选通道，不用你决定：

- **运行时注册**（`pi.themes.upsert`，ADR 0249）：**没有图片的主题**走这条，改完立刻生效、不重载。
  代价是宿主消毒时不给资源解析器，`url()` 只能是 `data:`。
- **静态贡献**（`themes/live.css` / `live-light.css`，ADR 0248）：**带图片的主题**走这条。
  宿主在加载时读取并消毒这些文件，允许引用 manifest 里声明过的包内资源
  （`plugin-asset://<pluginId>/<path>`），代价是一次插件重载（约 0.3 秒）。

已知取舍：**每个基底只有一个静态文件**，所以同一个基底上两套都带图片的主题会共用
`live.css`，后保存的那套生效。

## 图片

完整链路见 **[docs/image-pipeline.md](docs/image-pipeline.md)**（含流程图与宿主分层说明）。规则：

- **唯一来源**：你在系统文件选择器里选的本地 PNG（只收 PNG，魔数校验）。
- **存在哪**：插件的**数据目录** `pi.plugin.getDataPath()/images/<时间戳>-<4 位随机>.png`。
  不在插件包里 —— 开发插件监听器递归盯着插件包，往包里写文件会重载插件并关掉面板窗口。
- **怎么被用**：主题 CSS 里写它的**绝对路径**（正斜杠）。宿主会解析这个绝对路径并把字节交给
  渲染进程（ADR 0255），所以主题通过 `pi.themes.upsert` 注册即可生效，**零重载**。
- **每次上传都是新文件**，不按内容去重；一张图只属于一个主题（登记表里记 `owner`）。
- **删除**：文件消失，同时把所有设计里对它的引用清成「没有图片」，不需要先让谁松手。
  图片库还会列出数据目录里没有登记记录的文件（孤儿），可单独清理。
- **看得见的前提**：宿主每一栏都有自己的不透明底色（`.app-shell` / `.main-pane` /
  `.composer-shell` …），底图藏在它们后面 —— 用「一键透出」把上层放开。左栏图片走
  `--ds-bg-sidebar-image`，是唯一开箱可见的位置。
## 权限

只声明三个，均为第三方插件做同样的事所需的公开权限：

```text
ui.panel    独立面板窗口
ui.view     停靠工作面板视图
ui.theme    贡献主题
```

不申请 `fs.*`、不申请网络、不申请 `agent.*`，不读工作区，不联网。

## 宿主强制的限制（插件一视同仁，也不额外加码）

| 限制 | 来源 |
| --- | --- |
| 单个主题 CSS 文本 ≤ 256 KB | `packages/plugin-sdk/src/theme-css.ts:1` |
| 单个主题声明的资源文件合计 ≤ 4 MB | `theme-css.ts:15` / `crates/host-core/src/plugins/validation.rs:541` |
| 资源扩展名白名单 7 种：png / jpg / jpeg / webp / avif / svg / woff2 | `validation.rs:538` |
| 运行时注册通道的 `url()` 只能是 `data:` | ADR 0249 |
| 声明的资源文件必须真实存在，否则整个插件 `PLUGIN_INVALID` | `validation.rs:230-236` |

关于「图片算不算主题大小」：256 KB 只管 **CSS 文本**，图片以 `plugin-asset://` 路径引用、
不占这 256 KB；但图片**字节**另外算在上面那个 4 MB（每主题）预算里，所以它不是免费的。

插件本身**不设**主题数量上限，也不设设置大小上限 —— 宿主对两者都没有限制。

## 为什么用 `node:fs` 写自己的主题文件

这是本插件唯一一处需要解释的实现选择。

- 主题贡献的 CSS **必须位于插件包内** —— 宿主用 `resolveInsidePlugin` 解析
  `contributes.themes[].path`（`apps/desktop/electron/main/plugin-runtime.ts`）。
- 而 `pi.fs` 的根只能是工作区或用户选定目录（`packages/plugin-sdk/src/fs-policy.ts:16`），
  写不到插件自己的包内。
- 插件进程本身是普通 Node 进程（`utilityProcess.fork`），Node 内建模块可达 ——
  这一点在 `docs/spec/07-plugins/04-plugin-security.md` 的「未强制」一节里写明了。

因此写盘走 `node:fs`，但范围被刻意收窄：

- 只写自己的包内路径：`themes/live.css`、`themes/live-light.css`、`themes/img/<哈希>.png`、
  以及 `manifest.json` 里那两个静态主题的 `assets` 字段。
- 写文件前再解析一次目标路径，父目录必须等于预期的 `themes/` 或 `themes/img/`，否则拒绝。
- 资源只在白名单扩展名内（本插件只产出 `.png`），hash 只接受 `[0-9a-f]{8,64}`。
- manifest 写入前先 `JSON.parse` 自检，解析不过就绝不替换原文件（manifest 坏了插件就加载不了）。

面板无法让插件写到上述范围之外的任何位置，插件也不读工作区、不联网。

## 设计边界（已知取舍）

- **没有 `windowAppearance`。** 原生窗口底色是**按插件**声明的，而一个插件里有 5 套以上
  配色，任何单一取值都会对不上多数主题，所以本插件不声明它。代价是拖动窗口尺寸时可能
  有一帧露出宿主的默认底色。
- **文字层次用实色。** 宿主用 `color-mix` 的白色/黑色 alpha 阶派生四级文字；工坊改用实色
  十六进制，这样对比度可精确计算、值也能直接手改。
- **预览是复刻体，不是真窗口。** 它按 1280×800 逻辑尺寸渲染再整体缩放，token 名与宿主完全
  一致，但版面细节（图标、字体度量）是近似。最终确认请在真实窗口里看。
- **切主题要等一次重载。** 带图片的主题走静态通道，所以「保存」到「窗口换色」之间有一次
  插件重载（约 0.3 秒）；没有图片的主题是即时的。

## 校验

```bash
# 仓库根目录
pnpm pi-plugin check "C:\Code\PiPlugProjects\pi-desktop-plugin-pi-theme-studio"
```

输出应为 `OK pi.theme.studio@0.5.0`。它用宿主真实的 `validateManifest` +
`validateContributions` 校验 manifest，并检查声明的每个资源文件是否真的存在。
